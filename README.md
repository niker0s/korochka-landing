# Корочка — лендинг доставки пирогов

Демонстрационный заказ: одностраничный сайт пекарни. Статичный HTML/CSS/JS,
без сборщиков и без зависимостей. Открывается двойным щелчком по `index.html`,
но правильнее — через локальный сервер (см. ниже).

## Как посмотреть

```powershell
cd "D:\MyProjects\New sessions\session-2026-10-30\zakaz-01-pirogi"
python server.py
```

Затем открыть http://127.0.0.1:8000/

`server.py` — маленький сервер на стандартной библиотеке Python: отдаёт файлы
сайта и принимает заявки с формы. Ставить ничего не нужно.

Если нужен только внешний вид без формы, хватит `python -m http.server 8000`
или двойного щелчка по `index.html` — но тогда кнопка «Отправить заявку»
будет ругаться, что сервер недоступен.

## Приём заявок

Заявка уходит на `POST /api/order`. Сервер проверяет поля, складывает заявку
в `orders.jsonl` и, если настроен Telegram, отправляет сообщение.

Настройка — файл `.env` рядом с `server.py` (образец в `.env.example`):

```
TELEGRAM_BOT_TOKEN=123456789:AA...
TELEGRAM_CHAT_ID=000000000
```

Порядок:

1. В Telegram открыть **@BotFather**, команда `/newbot`, придумать имя — он выдаст токен.
2. Вписать токен в `.env` в `TELEGRAM_BOT_TOKEN`.
3. Написать своему боту любое сообщение (нажать «Start»).
4. Запустить `python find_chat.py` — скрипт покажет `chat_id`.
5. Вписать его в `.env` в `TELEGRAM_CHAT_ID` и перезапустить `server.py`.

Без токена сервер тоже работает: заявки пишутся в `orders.jsonl`, в консоли
видно «Telegram не настроен». `.env` в git не попадает, в чат токен не выводим.


Что уже защищено: длина полей, обязательные поля, ограничение 10 заявок
за 10 минут с одного адреса, служебные файлы (`.env`, `server.py`,
`orders.jsonl`) наружу не отдаются.

Без согласия на обработку данных заявка не принимается: галочка в форме
проверяется и в браузере (`script.js`), и на сервере (`validate()` в
`server.py`). Политика — страница `privacy.html`.


## Что внутри

| Файл | Что делает |
|---|---|
| `index.html` | вся страница: 7 блоков + шапка и подвал |
| `styles.css` | оформление: токены, сетки, адаптив, анимации |
| `script.js` | мобильное меню, появление блоков, проверка формы, отправка заявки |
| `server.py` | сервер: отдаёт файлы и принимает заявки, пересылает в Telegram |
| `privacy.html` | политика конфиденциальности — отдельная страница, ссылка из формы и подвала |
| `find_chat.py` | помощник: находит `chat_id` для бота |
| `assets/img/` | 4 фотографии (временные, см. `CREDITS.md`) |
| `assets/fonts/` | Alegreya и Onest, локально — сайт не зависит от Google |

Блоки страницы сверху вниз:

1. полоса с тем, что сегодня в печи;
2. шапка (липкая, с мобильным меню);
3. герой: заголовок, кнопки, три факта, фото в арке;
4. фраза «Пирог должен быть тёплым» на фоне корки;
5. меню — две колонки, сладкие и сытные, с ценами;
6. «Три шага» + фото пирога;
7. отзывы;
8. заказ: контакты + форма;
9. подвал.

## Как менять

- **Тексты и цены** — прямо в `index.html`, они лежат обычным текстом.
- **Фотографии** — заменить файлы в `assets/img/`, сохранив имена. Пропорции:
  герой 4:5, остальные 4:3 или 1:1.
- **Цвета и шрифты** — блок `:root` в начале `styles.css`. Например
  `--berry` — акцент, `--butter` — кнопки.
- **Телефон, адрес, почта** — сейчас заглушки `+7 495 000-00-00`,
  `hello@korochka.ru`, «улица Пироговая, 14». Меняются поиском по файлу.
- **Политика конфиденциальности** — `privacy.html`. Если меняются состав данных
  или срок хранения, правится и там, и в подписи галочки в форме.

## Что это пока не умеет

- Нет карты проезда и cookie-баннера. Политика конфиденциальности и
  разметка `schema.org` (пекарня, часы, меню с ценами) уже есть.
  Cookie-баннер не нужен, пока на сайте нет аналитики и рекламных куки.
- Фотографии временные: лицензии в `CREDITS.md`, для клиента нужны его снимки
  или купленный сток.
- `orders.jsonl` — временное хранилище. Для потока заявок нужна база или
  выгрузка в таблицу; сейчас файл просто копится.
- Хостинг: обычный статический хостинг (GitHub Pages, Netlify) форму НЕ
  обслужит — `server.py` там не запустить. Нужен Python-хостинг или VPS
  (например, Timeweb, Beget, любой сервер за 200–500 ₽/мес). Второй вариант —
  оставить сайт статичным и прикрутить serverless-функцию.

## Куда выкладывать

**Демо опубликовано:** https://korochka-landing.onrender.com (Render, бесплатный
тариф — засыпает без посетителей, первый заход после паузы ~30 секунд).

Подробно, с командами и настройками — в `DEPLOY.md`. Кратко:

1. **Хостинг клиента с Python** — залить папку, запустить `python server.py`,
   поставить автозапуск. Домен направляется на сервер.
2. **VPS** — то же самое плюс systemd/планировщик для автозапуска.
3. **Статика + serverless** (Netlify Functions, Vercel) — форма отправляет
   запрос в функцию, функция — в Telegram. `server.py` тогда не нужен.
4. **Render.com** — бесплатный Python-хостинг для демо: ссылка работает, но
   сервер засыпает через 15 минут без посетителей.

Выбор — за клиентом и зависит от того, что у него уже оплачено.

## Сдача клиенту

`Инструкция-клиенту.md` — что отдать владельцу сайта: как менять тексты, цены,
телефон, фотографии и цвета, и что лучше не трогать.

## Как это сделано

- Одна страница, обычные `<section>`, без фреймворков.
- Тема: тёмный «печной» фон, тёплый бумажный блок меню, ягодный акцент.
- Типографика: Alegreya (заголовки, курсив) + Onest (текст). Файлы шрифтов
  лежат локально, поэтому страница не тормозит и работает без интернета.
- Волнистый край у блока меню нарисован CSS-маской, а не картинкой.
- Фото в герое — арка: `border-radius: 320px 320px 22px 22px`.
- Анимации: один вход героя при загрузке и мягкое появление блоков при
  прокрутке. При `prefers-reduced-motion` всё отключается.
- Референсы форм и блоков — коллекция https://21st.dev/community/components
  (тёплые градиентные фоны, hero с градиентом, карточные меню). Компоненты там
  на React и Tailwind, поэтому переносился дизайн, а не код: у нас статичный
  HTML, как требует стек проекта.

## Проверено

- Страница открывается в браузере: http://127.0.0.1:8000/
- Мобильное меню открывается, ссылки закрывают его.
- Форма: пустая отправка даёт три ошибки, с заполненными полями — «Заявка
  принята», поля очищаются, заявка появляется в `orders.jsonl`.
- Согласие: без галочки форма показывает «Без согласия на обработку данных
  заявку принять нельзя» и не отправляет; сервер на такую заявку отвечает
  422 с той же ошибкой. Клик по ссылке политики внутри подписи галочку не
  переключает.
- `privacy.html` открывается, шрифты и стили те же, консоль без ошибок.
- Сервер: пустая заявка → 422 с текстами ошибок, нормальная → 200, 11-я подряд
  с одного адреса → 429, запрос `/.env` и `server.py` → 404.
- Кириллица проходит без искажений (проверено Python-клиентом и файлом заявок).
- Консоль браузера без ошибок.
- Телефон 390 px и планшет 768 px: горизонтальной прокрутки нет, меню, шаги,
  отзывы и форма читаются, кнопка «Выбрать пирог» видна на первом экране.
- Lighthouse (доступность, best practices, SEO) — по 100 баллов, замечаний нет.
- После правок клиент сразу видит новую версию: HTML, CSS и JS сервер отдаёт
  с `Cache-Control: no-cache`, картинки при этом кешируются как обычно.
